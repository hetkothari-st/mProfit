# Bug hunt — 2026-09-22

Code-level review of main @ 585f5a1f, focused on code merged after the
2026-09-16 security audit (CA/client access, family views, billing, AI
assistant, loans given). Status legend: `[x]` fixed · `[ ]` open.

## Fixed (branch `fix/serious-bug-hunt`)

- [x] **F7 [P1 revenue] Paid plan never expired.** `planExpiresAt` was written at
  checkout and never read. `effectivePlan()` now treats an expired paid plan as
  FREE in the access-token claim, `/me` payload, AI quota and AI context.
  Test: `test/services/planExpiry.test.ts`.
- [x] **F3 [P1 data leak] Family view counted portfolios shared into another
  family.** Member slices used `portfolio: { userId }`; now limited to personal
  portfolios + those shared into the family in view (dashboard family view,
  Family page wealth/attention/member holdings).
  Test: `test/services/family/crossFamilyBleed.test.ts` (reproduced ₹7.77L bleed).
- [x] **F4 [P1 data leak] CA asset-class limit ignored on HoldingProjection /
  CapitalGain / CashFlow.** Migration `20261006110000_ca_asset_class_derived_tables`
  adds the class check to the read AND the FOR ALL write policies (whose USING
  also grants SELECT); CashFlow (no class column) is withheld from a
  class-narrowed grant. Test: `test/security/ca-grant-scope.test.ts`.
- [x] **F5 [P1 hardening] No check that the DB role enforces RLS.** API now
  refuses to start in production on a superuser/BYPASSRLS connection (warns
  elsewhere). Test: `test/security/db-role-guard.test.ts`.

## Open (all fixed 2026-10-06: F8 in #188; F1, F2, F6, F9 on fix/bug-hunt-open)

- [x] **F6 [P2 authz] CA upload bypasses grant narrowing.** `caCreateImport` →
  worker runs `runAsUser(clientUserId)` (jobs/importWorker.ts:30,
  services/imports/import.service.ts:36), so transaction inserts skip the
  CA asset-class/portfolio checks — a CA limited to MF can import an equity
  contract note. `ensureDefaultPortfolio` creates a new portfolio in the
  client's account when the CA can see none in scope.
- [x] **F8 [P2 revenue] `/api/billing/verify-payment` is replayable.** Order /
  payment never recorded as consumed; re-posting the same captured triple resets
  `planExpiresAt` to now + cycle. Now exploitable because F7 enforces expiry —
  fix next. Also no check that the payment is captured / amount matches tier.
- [x] **F9 [P2 cost] AI daily quota race.** `checkQuota` at request start,
  `incrementUsage` only on stream completion (routes/aiAssistant.routes.ts:171,
  :313). Parallel requests all pass; errored/aborted streams never counted.
  Fix: atomic reserve before the call, refund on hard failure.
- [x] **F1 [P2 logic] CA "access until" ends 05:30 IST on the last day.**
  `parseScopeDate` stores `YYYY-MM-DDT00:00Z`; `getCaScope` (`accessUntil < now`)
  and SQL `app_is_active_ca_for` (`accessUntil >= now()`) cut access at the start
  of the day shown as "Until <date>". accessFrom starts 05:30 IST, not 00:00.
  caAccess.service.ts:851-858, :152; migration 20260923090000 :101-102.
- [x] **F2 [P2 logic] AI net-worth growth in family view mixes family and
  personal.** `current` = family net worth, 1/3/6/12-month history = caller's
  personal snapshot (ai/contextBuilder.ts:316-345). Most other AI builders
  ignore family view entirely.

## Test-environment note

`test/helpers/env.setup.ts` defaults `DATABASE_URL` to
`localhost:5432/portfolioos` BEFORE `.env` is loaded, so DB tests silently run
against whatever Postgres is on 5432 unless `DATABASE_URL` is exported in the
shell. Worth fixing so a worktree's `.env` is honoured.
