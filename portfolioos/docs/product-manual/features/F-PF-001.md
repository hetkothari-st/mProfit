# Provident Fund page and holdings

`F-PF-001` · Live · Roles: [R-FREE](../roles.md#r-free), [R-PLUS](../roles.md#r-plus), [R-FAMILY](../roles.md#r-family), [R-PRO](../roles.md#r-pro), [R-MANAGER](../roles.md#r-manager)

**What it does:** Shows your PPF and EPF holdings across all portfolios with a summary strip (**Invested**, **Current value**, **Unrealised P&L**), the holdings, a **Transactions** table of every PPF and EPF entry (date, name, type, quantity, price, amount) with edit and delete, and below it the **Auto-fetch accounts (EPFO portal)** section ([F-PF-005](F-PF-005.md)).

**Why it exists:** Page description: "Track your PPF and EPF balances, contributions, and interest".

**Where to find it:** **Asset Classes → PPF & EPF** (route `/provident-fund`; `/ppf` and `/epf` redirect here).

**Who can use it:** [R-FREE](../roles.md#r-free), [R-PLUS](../roles.md#r-plus), [R-FAMILY](../roles.md#r-family), [R-PRO](../roles.md#r-pro); [R-MANAGER](../roles.md#r-manager) for the managed person. Family view does not add other members' entries.

**Steps**
1. Open **Asset Classes → PPF & EPF**. With nothing recorded, the empty state "No provident fund yet" offers **Add first entry**.
2. Click **Add** and choose **PPF entry** ([F-PF-003](F-PF-003.md)) or **EPF entry** ([F-PF-002](F-PF-002.md)).
3. Click the pencil on a transaction to edit it in its form; click the bin, then **Yes** at "Sure?" to delete it (**No** cancels).
4. Use the download button for a holdings report ([D-PF-002](../dependencies.md#d-pf-002)).

**Controls**
| Control (exact label) | Type | What it does | Disabled / hidden when |
|---|---|---|---|
| **Add** → **PPF entry** / **EPF entry** | Menu button | Opens the PPF or EPF form | Never |
| Download report button | Button | Holdings report for PPF and EPF ([D-PF-002](../dependencies.md#d-pf-002)) | Never |
| Transaction edit / delete | Buttons | Edit in the matching form; delete after "Sure?" | — |

**Fields and rules:** Not applicable — see [F-PF-002](F-PF-002.md) and [F-PF-003](F-PF-003.md).

**Settings and toggles here:** None.

**Results:** Nothing changes by viewing.

**Errors and troubleshooting**
| Message / symptom | Cause | Fix |
|---|---|---|
| "Failed to delete" | Server error | Try again |
| Balance fetched from EPFO doesn't show in the holdings | Auto-fetched passbook rows are stored separately and don't create holdings (see [F-PF-006](F-PF-006.md)) | Add an **Opening / current balance** entry manually |

**Limitations:** Holdings come only from manual entries; auto-fetched or uploaded passbooks don't change them. The transactions table shows up to 200 entries per asset class. PPF and EPF have no market price, so **Current value** comes from the shared asset-page rules ([D-PF-001](../dependencies.md#d-pf-001)).

**How it works:** The page is the shared asset-class page configured with asset classes PPF and EPF and two entry forms; it reads each portfolio's holdings and `GET /api/transactions?assetClass=PPF|EPF` (200 per class). Holdings group entries by account number (UAN / PPF account number) when given, otherwise by the employer or bank name typed.
